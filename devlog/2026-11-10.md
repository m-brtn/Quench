## Problems and solutions

- **The weather section lost every frame** ("Destroyed texture [... SwapChainTexture] used in a submit", a black
  page). The rain maps a small download every other frame; the backend's `map()` waited with `emscripten_sleep`
  inside the frame callback, the browser took the frame back and expired the canvas's texture. Solution: a
  download's staging buffer is mapped when its command buffer is submitted, the callback copies the rows between
  frames, the fence signals after the queue's work and the reads; `map()` after the fence does not wait.
- **A scripted run used the page's size** (725 x 760 instead of `--window 960x540`). The shell gave the canvas a
  CSS size, which makes SDL leave the size to the page. Solution: no CSS size; fill-document only on the screen.
- **The page never learned that the program ended** (Emscripten 6.0.13 ignores `Module.quit` and does not call
  `onExit` while the runtime stays alive): `web_check.mjs` ran into its timeout. Solution: `quench_main` calls the
  shell's `Module.quenchEnded(code)` at the end of `SDL_AppQuit`.
- **Headless Chrome stepped an offscreen batch at 60 Hz** (about 5 minutes). Solution: offscreen runs in a browser
  take their frames from timers (`SDL_HINT_MAIN_CALLBACK_RATE` 1000): the demo's batch in about 2 minutes.
- **A page on the screen threw at the quit** ("Failed to execute 'insertBefore' on 'Node'"). SDL 3.4.18's
  fill-document window moves the body's other elements into a hidden element and, closing, puts the canvas back
  before its former next sibling, which is no longer in the body. Solution in the shell: the canvas is alone in a
  `#stage` element; a status text moves to the end of the body so that it is seen over a filling canvas.
- **The web build did not link after `tools/format.sh`**: clang-format had split `!==` inside an `EM_ASM_INT` into
  `!= =`. Solution: `!=` there, with a comment. The earlier browser runs were of the build before the format.
- **An error line at every quit of the weather section** ("cannot map a download of 1792 bytes"): the closing
  device aborts the pending map. Solution: only a map that failed (`WGPUMapAsyncStatus_Error`) is logged.
- **`tools/check.sh full` ended with exit 2** after its last step had passed: the script was edited (the `web`
  step) while bash was reading it. Not a failure of a step; noted so that nobody edits it during a run again.
- **Clicks from the browser automation stuck** (pressed, never released) on ImGui buttons: replaced by synthetic
  pointer events on the canvas. A limit of that tool, not of the engine; a person's clicks were not tried.
- **One batch run in Cursor's browser tab reloaded near `particles.txt`**, cause unknown; not seen again in two
  more runs there or in four runs in headless Chrome.
- **Safari drew nothing.** SDL's Emscripten video driver sets the canvas to 1 x 1 and treats a CSS size other than
  exactly 1 as "the page sizes the canvas". Under Safari's page zoom (115% on the user's Mac) a 1 x 1 canvas
  measures a little under 1, so SDL left the size to the page: a 0 x 0 window, no fill-document, no frame
  presented. First solution: `cmake/patches/SdlCanvasProbe.cmake` accepted 0.5 to 2.5 as the probe's own size.
  Final solution (14:20), without a patch: the app gives the canvas its CSS size before it creates the window, so
  SDL takes the page's size ("external size") and the probe's measure does not matter.
- **`demo_batch_vulkan` failed now and then** (`VUID-vkCmdDraw-None-09600`: an image sampled in
  `SHADER_READ_ONLY_OPTIMAL` was in `TRANSFER_SRC_OPTIMAL`). Cause: SDL GPU's Vulkan driver defragments its memory
  at a submit (every submit when no window is claimed, so in every offscreen run) and copies textures and buffers
  into new ones, leaving the old image in `TRANSFER_SRC_OPTIMAL`; it skips allocations with pending transfers but
  not resources that another open command buffer has bound. The engine submits small command buffers while the
  frame's is open (the rain's cover readback every other frame, uploads, lazy initialization). A temporary log in
  the build tree's SDL showed 190 to 260 texture moves per batch run; in a failing run the texture named in the
  error ("render no transmittance") was moved during such a submit just before it. Only SDL's Vulkan driver
  defragments; SDL's `main` (`8b6ae5d`) has the same code. Solution: `SdlVulkanDefrag.cmake` (the driver counts its
  open command buffers and defragments only when no other one is), and the rain's readback in the frame's command
  buffer through `CommandBuffer::completionFence()`.
- **Safari showed a black page now and then until the window was resized** (0.13.0, Safari 27.0.1, page zoom
  100%, pixel ratio 2; the user saw about 1 in 3 to 5 loads black, the whole page without the panels). The script
  in the pages recorded the same sequence in black and shown pages: SDL's canvas probe (1 x 1, then 2868 x 2294),
  one `configure` in an animation frame, every `getCurrentTexture` in an animation frame, about 59 frames per
  second, no warning or error; a copy of the canvas through `drawImage` had a mean of 140.2 to 140.7 of 255 in
  the black page (s4) as in the shown ones (s1 to s3). So the frames were rendered, and Safari did not put them on
  the screen until a new size made the backend configure the canvas again. Not reproduced in Playwright's
  headless WebKit (0 of 7, whose screenshots do not go through Safari's compositing). Solution in
  `WebGpuDevice::acquireSwapchainTexture`: 20 frames after the first configuration, the canvas is configured one
  pixel narrower and back within one frame. Earlier tries to make it black on purpose (tabs opened in the
  background, other nudges) gave mixed results; about twelve demo tabs at once made all of them black, which was
  not counted.
- **Blotches that crawl on evenly lit surfaces with `AmbientOcclusion::ScreenSpace`.** Seen by the user in the
  Outpost game (a zoomed screenshot of a shaded wall). Cause: GTAO's term, 2 slices of 4 steps to either side over
  a screen radius of about 180 pixels in that view (a far camera with a narrow field of view), is noisy per pixel;
  the 4 x 4 blur left blotches about 8 pixels wide, and because the noise changed every frame under TAA, which
  did not average them out, they moved. Found by switching parts off in offscreen captures at 4536 x 2835 (without
  occlusion the surface is smooth; the sharpening and the game's outlines made no difference) and by numbers on a
  flat shaded surface (RMS in 8-bit levels of the image minus its 11 x 11 mean / of two captures 7 frames apart):
  no occlusion 0.42 / 0.15; 1, 2 (the default), 4, 8 slices 1.48 / 3.04, 1.45 / 2.37, 1.26 / 1.73, 0.83 / 1.23;
  the same noise every frame 2.15 / 0.65 with 2 slices and 1.08 / 0.26 with 8 (still, but the blotches stay). So
  neither more slices nor a fixed noise is enough. Solution: the term is accumulated over up to 16 frames (stage
  17:40).
- **2 x 2 pixel steps in the accumulated occlusion.** With the term free of noise, the blur's equal weights over
  4 x 4 texels showed as steps on every occlusion gradient (pixel pairs share a window; rows of 78, 78, 74, 74,
  72, 72 in a sphere's contact shadow of the demo's capture; the noise had hidden them). Solution: tent weights
  2 texels to either side once a texel has a history; that alone let more noise through (0.84 / 1.00 in the
  measure above), so the history takes in the 3 x 3 mean of the new terms (0.57 / 0.48).
- **The tent cost 0.20 ms.** Computed per texel inside the blur's 16-tap loop: `gtao` 0.69 ms in the shadows
  section. Solution: the weights per axis in two `float4` set up before the loop: 0.50 ms.
- **`renderer_screen_space_ambient_occlusion` failed on SDL GPU** (the fallback from `RayTraced` was no longer the
  same image as the first frame, mean 0.739): a first try took the noise's frame from the renderer's frame
  counter. Solution: the noise counts the frames of the occlusion's own history, 0 when it starts over.
- **A shell around a model shadows the model.** The Outpost game's outlines are inverted hulls 4.5 to 7 cm
  around their models, placed through `SceneAssets::addModel`, which gave a game no way to place a model that
  casts no shadows; the shadow maps draw both sides of a caster. From the default camera distance (108 m) the
  cascades' texels and bias hid it; zoomed in, the cascades get finer than the gap and the hull shadows its own
  model: in bands along the facets at the wheel's nearest zoom (45 m, the user's screenshots), over the whole lit
  side at 30 m (the agent's captures). Solution: `SceneAssets::setCastsShadows(instance, false)` for the hulls.
  Such an instance is not in the ray tracing structures either (no hit shading in the game), so the game no
  longer hides the outlines with ray-traced shadows and occlusion.

## Limitations and open questions

- The final canvas fix has not been looked at in Safari itself (the user's first look was with the SDL patch).
  Later (16:20) the user opened it in Safari: it runs, apart from the black page above.
- The Safari fix is a workaround of a cause inside Safari that was not found; its evidence is 9 pages and two
  rounds of reloads, against a failure rate of roughly 20 to 40%. Not reported to WebKit. The published site
  (0.13.0) does not have it until the next release is deployed.
- `SdlVulkanDefrag.cmake` stays until an SDL release fixes #16685. Uploads, lazy initialization and the skinning
  with pass timing still submit their own command buffers while the frame's is open.

- Run in Chromium on one Mac only. Not in Safari, Firefox, Chrome on another system, or any phone. Nobody has
  played the demo in a browser: input was scripted or synthetic. Nobody has listened to it.
- No GPU unit tests on the WebGPU backend (the test executables are not built for the browser): it is covered
  through the apps' scenarios and captures only. No web golden images: the captures are compared with Metal's.
- A capture, `Device::download`, `waitIdle` or a fence wait inside a frame on the screen still waits and costs
  that frame its swapchain texture. Scripted captures therefore run offscreen.
- Depth textures and, without `float32-filterable`, 32-bit float textures are sampled with nearest filtering; no
  storage textures, line fill mode, 3D blit sources, blits into depth textures or swapchain downloads; no GPU
  timing, HDR output or ray tracing (the fallbacks run).
- One thread: jobs run on the frame thread; the Web Audio output mixes on the main thread
  (`ScriptProcessorNode`), underruns under load not measured. No null audio device there.
- The user directory is in memory: settings, saves and captures are gone after a reload.
- Cooked textures are BC7 in web builds; a phone's browser would need Basis Universal files (not tried).
- No work on download size or load time; nothing hosted (everything from `127.0.0.1`).
- `emdawnwebgpu` comes with the installed Emscripten (Homebrew, not pinned): another Emscripten can bring
  another `webgpu.h`.
- Observed, not changed: `tests/golden/metal/apple-m4-pro/hello.png` is older than the sample's text (it shows
  "t = 1.00 s, 120 ticks" and "2.00 px/pt"; the Mac's capture differs from it by 0.0673% and passes). The web
  capture differs by 0.2153% (limit 0.1%), in the text lines only (x 40..331, y 82..105), so `step web` does not
  compare it.
- Nothing is committed. A push to `windows-build` starts the Windows workflow (about an hour).
- GTAO's accumulation: not looked at in motion on a screen by anyone (the user checks the Outpost game on the
  Mac next). Not run: `tools/check.sh full` (debug, asan, tsan, `wasm-node`, the iOS Simulator), `step web`, a
  phone, SDL GPU's frame times. Its history follows the camera only: around moving objects the occlusion settles
  over a few frames (no motion vectors without the ray tracing prepass). Two more half-size `Rgba16Float`
  targets (8.3 MB at 1080p). The first frames after a cut still show one frame's noise.
- Seen in the Outpost captures, not looked into: the walker's outline smears a little while it walks (TAA on a
  moving object; the outlines are the game's inverted hulls).
- `SceneAssets::setCastsShadows` has no test of its own (the game uses it; `Scene::setCastsShadows` is tested).
  The full gates were not run after it either.
