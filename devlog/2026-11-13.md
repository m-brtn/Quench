# Devlog — 2026-11-13 (Friday)

## Goal of the day

The user's request through the Outpost game ("make the save on the web survive a page reload"): a game's user
directory in a browser build (its save, its `settings.json`) was in Emscripten's in-memory file system and lost at
every reload. It is now kept in the browser's IndexedDB, for every game built with `quench_add_game()`, with no
change in a game's code.

## Stages

- **12:30 — The default user directory in IndexedDB** (`src/app/SdlFileSystem.cpp`; `-lidbfs.js` on `quench_app`
  for Emscripten). Only the default user directory (`SDL_GetPrefPath`, `/libsdl/<organization>/<name>/`); what
  `--user-dir` names stays in memory, so the scripted checks (`--user-dir /user`) stay hermetic.
  - **One database per app.** IDBFS names its database after the mount point (read in Emscripten 6.0.13's
    `src/lib/libidbfs.js`: `getDB(mount.mountpoint, ...)`, `indexedDB.open(name, 21)`, store `FILE_DATA`, one
    record per file and directory keyed by its absolute path). It is mounted at the user directory itself, so the
    database is `/libsdl/<organization>/<name>`: the demo's `/libsdl/Quench/Quench Demo`, Outpost's
    `/libsdl/Outpost`. A mount at `/libsdl` would have given every page of the GitHub Pages origin one database,
    and one page's store would have removed the other's files.
  - **Loaded before the first read.** `makeSdlFileSystem` runs inside `SDL_AppInit`, on the main program's stack
    before the loop and before the game's `init` (which reads settings and saves). It waits there for the stored
    files through Asyncify (`EM_ASYNC_JS`), as the WebGPU device's start already does; a `preRun` step in the shell
    would have had to know the organization and name in JavaScript and would not cover a `CUSTOM_MAIN` program.
    The time limit is 5 s (`kUserFilesLoadTimeoutMs`). The load runs IDBFS's steps itself (local set, remote set,
    then the copy) so that an answer after the limit is dropped instead of filling the directory later.
  - **Stored after each write.** After every successful `writeUser` (the backend's only operation that changes
    user files) `IDBFS.syncfs(mount, false, ...)` starts in the background; one at a time, and a write during a
    store starts one more when it ends.
  - **Never hang, never abort.** No IndexedDB (also Node.js, and a browser that throws on access), a failed mount
    or load, or no answer within 5 s: the mount is undone, the directory is in memory as before, and the log says
    once "user files: in memory only, lost when the page closes: <why>". A failed store later is one warning
    ("WARNING: fs: the user files were not stored in IndexedDB ...") until a store succeeds again; `writeUser` has
    succeeded. Desktop, iOS and `wasm-node` do not compile the code (`QUENCH_PLATFORM_WEB`; `wasm-node` is headless
    and builds no `quench_app`).
  - **State for scripts:** `Module.quenchUserFiles` (`dir`, `kept`, `busy`, `again`, `failed`, `entries`, `ms`,
    `error`).
- **12:40 — The persistence check** (`tools/web_check.mjs`, `tools/check.sh step web`). `web_check.mjs` takes

## Problems and solutions

- **`IDBFS` from an `EM_JS` body.** This Emscripten has no `FS.filesystems`; `IDBFS` is a library symbol that
  `FS` depends on only when `-lidbfs.js` is linked. `EM_JS_DEPS(quench_user_files, "$FS,$IDBFS,...")` names it.
- **clang-format inside `EM_JS`.** It writes `!==` as `!= =`: the JavaScript uses `!=` and no arrow functions (noted
  in the code, as in `App.cpp`).
- **The flag of the backend is unused off the web** (`-Wunused-private-field`, found by the release build of
  `quick`): `[[maybe_unused]]`.

## Limitations and open questions

- Only headless Chrome on the Mac ran it. Not tried: Safari, Firefox, a phone's browser, a private window, storage
  disabled, a quota error, the 5 s limit (the paths without IndexedDB were read in code, not run).
- Not kept: files written in the moment before a tab closes (their store had not ended; there is no store on
  `pagehide`), another browser, profile or device, a private window after it closes, cleared or evicted site data
  (best-effort storage: `navigator.storage.persist()` is not asked for).
- Two tabs of one app share one database; each stores its whole directory, so a store of one can overwrite or
  remove the other's newer files. No lock between tabs.
- If IndexedDB answers after the 5 s limit while the files are being copied in (not while it is opened), the copy
  still writes into the in-memory directory.
- Every store compares the whole directory (cheap for a save and a settings file; captures in the user directory
  are stored too).

## 14:07 — Deferred assets: files a web page fetches while it runs

Asked for Outpost (its page loaded 87 MB before the first frame, 66 MB of it music): assets that a browser build
leaves out of its `.data` package and downloads while the program runs. Not committed, no version change.

- **CMake.** `quench_add_game(... DEFERRED_ASSETS <pattern>...)`: a file, a directory or a `file(GLOB)` expression
  relative to the asset root. In a web build `cmake/StageAssets.cmake` copies the matching files to
  `<OUTPUT_NAME>.assets/<path>` beside the page instead of the stage, removes them from the stage if an earlier
  build put them there, removes files from the folder that are no longer deferred, and writes their list
  (`folder <name>`, then `<size> <path>`) only when it changes; the list is packed at
  `/quench/deferred_assets.txt`. Both `--preload-file` flags are `SHELL:` flags (CMake merged two plain ones into
  one, and the link failed). A pattern that matches nothing is a warning. Other platforms ignore the option. The
  staging also keeps Finder's `.DS_Store` out (and removes one an earlier build staged), and a file two sources
  share is copied once, from the later one (before, both copies ran each time).
- **API** (`include/quench/core/FileSystem.h`): `fs::AssetState` (`Missing`, `Present`, `Deferred`, `Fetching`,
  `Failed`), `fs::assetState(path)`, `fs::requestAsset(path, priority = 0)`; two virtual functions on
  `fs::Backend` with defaults (exists: `Present`, else `Missing`; a request does nothing), forwarded by the overlay.
  No progress in bytes (nothing needs it yet).
- **The browser** (`src/app/SdlFileSystem.cpp`, `DeferredAssets`): reads the list when the file system is made; a
  request queues the file; at most two downloads at a time with `emscripten_async_wget2` (XMLHttpRequest, written
  into the asset directory when complete, callbacks on the main thread between frames, no Asyncify), the highest
  priority first and in the order asked among equal ones; asking again raises a waiting file. A failure is tried
  once more, then `Failed` with a warning. Log: `assets: fetched deferred/greeting.txt (85 B, 8 ms)`.
- **Scenarios:** command `asset_request PATH [PRIORITY]`, values `asset_state:PATH` (0..4) and `asset_size:PATH`
  (bytes `fs::readAsset` reads, -1). `tools/web_check.mjs --not-found PATH` answers a file with 404 and counts it.
- **The check** in `tools/check.sh step web`: hello now has `ASSETS assets` with `DEFERRED_ASSETS deferred` (two
  small text files; on the desktop and iOS they are bundled). Its `hello.data` is the 71-byte list; the step checks
  that the text is not in it and the file is beside the page, then runs `scenarios/deferred_web.txt` in headless
  Chrome with `unserved.txt` answered 404: both `Deferred` at the start, `greeting.txt` unreadable, then fetched and
  read with 85 bytes; `unserved.txt` two requests, `Failed`, no hang; 10 of 10, about a second.
  `tools/publish_web.sh` copies `hello.assets/` into the site. Core test `fs_asset_state` (the default backend and
  the overlay).
- **Gates.** `tools/check.sh quick core app hello`: 100 of 100 (6.3 s). `step web`: passed in 158.9 s (hello 21 of
  21, deferred assets 10 of 10 with 2 answers 404, the demo's batch 806 of 806 with 41 captures compared, the user
  files across three loads, both pages on the screen's path). `full`: passed in 1243.2 s: debug 690, release 833,
  ASan 690, TSan 690, `wasm-node` 206, iOS Simulator 524 tests, all passed; the Xcode project generated; a new game
  built and started; the skill check passed. The build folders of `asan`, `tsan`, `ios-sim-*`, `wasm-node` and
  `ios-xcode-check` were deleted afterwards (disk space).
- **Limitations.** Run only in headless Chrome on the Mac. A fetched file stays in memory for the session (the
  in-memory file system, as packed files do) and is not kept between visits by the engine (only by the browser's
  HTTP cache, if at all). No timeout of its own: a stalled connection leaves a file `Fetching` until the browser
  gives up. Priority order with more than two waiting files was read in code, not run. An `AssetManager` load of a
  file not yet there fails like any missing file. Outpost's use needs a release with this before its pin can move.

## 20:20 — `quench_net`: asynchronous HTTPS requests (the transport for an in-game assistant)

Asked for a later in-game AI assistant (a player's own key for an OpenAI-compatible API). Built in a separate
working copy on the local branch `assistant-foundation` (0.17.0 plus its devlog commit). Not committed, no version
change.

- **API** (`include/quench/net/Http.h`, `FakeNetwork.h`). `net::Client` with `send(Request, Handlers)` returning a
  `RequestId` or an error at once, `cancel`, `cancelAll`, `update()` once a frame; `Request` (method, URL, headers,
  body, `timeoutSeconds` 30, `maxResponseBytes` 16 MB, `streamBody`), `Response` (status, headers, body, bytes,
  seconds, `ErrorKind` and a message). Callbacks (`onHeaders`, `onChunk`, `onDone`) called from `update()` on the
  main thread only; `onDone` once per sent request, also after a cancel. The rules, timeouts, size limit and the
  log are in the client (`src/net/Client.cpp`, `Rules.cpp`); backends only move bytes (`src/net/Backend.h`).
- **Backends.** NSURLSession (`AppleBackend.m` and `.cpp`, macOS and iOS: ephemeral session, no cookies, cache or
  credential storage; the delegate on a serial system queue copies into a locked queue); the browser's fetch
  (`WebBackend.cpp`, `EM_JS`: AbortController, a ReadableStream reader, events queued in JavaScript and taken by
  `update()`); none (`NonePlatform.cpp`: Linux, Windows, `wasm-node`); the fake (`FakeNetwork.cpp`, every build).
- **Games.** `quench_add_game()` links `quench_net`; the skill has a section ("HTTP requests"); `tools/check_skill.py`
  checks names after `net::`.
- **Tests.** `tests/net/NetTests.cpp` (15 cases with the fake, label `net`), `tests/net/AppleNetTests.cpp` (11 cases,
  macOS) started by `tests/net/net_test_server.py --run` (a new `LAUNCHER` option of `quench_add_test_variant`),
  hello's `NetCheck.h` and `scenarios/net_web.txt` against new `/net/` paths of `tools/web_check.mjs`, run by

## 20:33 — Microphone capture (the recording side of the in-game assistant)

The user's next step for the voice assistant: hold a key, speak a few seconds, send a 16 kHz mono WAV to a
speech-to-text service. Built in this working copy (branch `assistant-foundation`, uncommitted, beside
`quench_net`); not released, no version change.

- **Headless (`quench_audio`):** `audio::Microphone` (`include/quench/audio/Microphone.h`, `src/audio/Microphone.cpp`):
  permission (`MicPermission`: unknown, not asked, asking, granted, denied, unavailable), states (idle, opening,
  recording, finished, failed), `start(MicDesc{rate 8..48 kHz, 16 kHz by default; limit up to 600 s, 30 s by
  default})`, `stop`, `cancel`, `update(dt)`, `level()` (a peak meter that falls by half in 0.1 s), `seconds()`,
  `takeRecording()` (`MicRecording`: mono float, `pcm16()`, `wav()`). The device's thread only writes the existing
  lock-free `SampleRing`; `update()` drains it on the main thread, measures, resamples (miniaudio's linear resampler,
  low-pass order 8) and cuts at the limit. The fake source (the default constructor) plays fed samples at the pace of
  `update`'s time. `encodeWavPcm16` beside `encodeWav` (a second `encodeWav` overload made `encodeWav({}, ...)`
  ambiguous, so it has its own name); decoding WAV from memory was already there (`decodeSound`).
- **Device (`quench_audio_device`):** `audio::makeMicrophone(jobs, MicDeviceDesc)`: miniaudio's capture device
  (mono f32 at the device's rate) opened and closed on jobs, one after another (`src/audio/MicrophoneDevice.cpp`);
  the permission through AVFoundation (`src/audio/MicPermissionApple.m`: `AVCaptureDevice` on macOS,
  `AVAudioApplication` on iOS; an app bundle without `NSMicrophoneUsageDescription` reports unavailable); on iOS the
  session goes to `PlayAndRecord` with `DefaultToSpeaker | AllowBluetoothA2DP` (and `MixWithOthers` for an ambient
  game) while recording and back afterwards (`quench_audio_session_record`); in a browser `getUserMedia` directly

## 21:15 — `quench_assistant`: a language model that operates a game through its tools

The module on top of `quench_net` and the microphone, in the same working copy (branch `assistant-foundation`). Not
committed, no version change. Built from the research notes of the day (OpenRouter's shapes and timings measured with
real requests, outside the repository).

- **API** (`include/quench/assistant/`). `ProviderSettings` with presets (`openRouterPreset`, `openAiPreset`,
  `localPreset`), its save without the key (`settingsToJson`), `Failure` and `ErrorKind` mapped from the transport
  and the HTTP status (`failureFromResponse`, the provider's own message, `redact`); `ToolRegistry` with `Tool`
  (name, description, `inputSchema`, MCP's annotations, a handler), `list()` and `callResult()` in the shapes of
  MCP's `tools/list` and `tools/call`, `validateSchema` (the subset a game needs), bad calls as error results;
  `ChatStreamParser` (server-sent events or one JSON body, from pieces cut anywhere) and `buildChatRequest`;
  transcription (JSON with base64 or multipart) and speech requests, `decodeSpeech` (PCM by its `Content-Type`, MP3
  through `audio::decodeSound`); `Assistant` with `ask`, `askByVoice`, `transcribe`, `speak`, `cancel`, `update`,
  the states, events, counters and a bounded history (`historyJson`, `setHistory`).
- **Decisions.** One operation at a time: a second is refused with "busy", not queued. Tool calls run one per
  `update()`, each visible for at least one update before it runs (cancel between a call's request and its result).
  The last of the 3 rounds sends `tool_choice: "none"`. The state summary goes before the player's words in that
  turn's user message, not into the history (a system message in the middle breaks some local servers' templates).
  A failed or cancelled turn is not kept in the history. `quench::json` decodes `\u` surrogate pairs as two
  three-byte sequences: the module repairs them in what it reads (core left as it is).
- **Games.** `quench_add_game()` links `quench_assistant` beside `quench_net`; the skill has an "Assistant" bullet
  and a section in `reference.md`; `tools/check_skill.py` checks names after `assistant::`; `tools/check.sh` maps
  the module's files to the label `assistant`.
- **Manual check.** `examples/assistant_check/` (`quench-assistant-check`, macOS, a command line program without a
  window, the key from `OPENROUTER_API_KEY` only).
- **Tests.** `tests/assistant/` (44 cases, label `assistant`, all on `net::FakeNetwork`), two stream fixtures written
  in the shape of recorded OpenRouter streams (`tests/assistant/data/README.md`; the recorded lines were cut at 300
  characters in the notes, so they could not be used as they are).
