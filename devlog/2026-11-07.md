## Problems and solutions

- **Xcode put re-cooked assets into the app one build late.** Cause: the merged folder was a folder reference in
  the app target's resources, and Xcode checks such a folder before the build in which the `<target>_assets` target
  changes it (the build's own log: `Staged 21 changed asset files` in the merged folder, no `CpResource` for it;
  the next build had the `CpResource`). The check of 2026-11-06 that found no delay changed files in a build in
  which CMake regenerated the project, which plans the copy again. Solution (decided without the user): no folder
  reference; a `POST_BUILD` command (Xcode's `CMake PostBuild Rules` phase, after the other phases, every build)
  runs `StageAssets.cmake` with `-DXCODE_BUNDLE=ON` from the merged folder into
  `$TARGET_BUILD_DIR/$UNLOCALIZED_RESOURCES_FOLDER_PATH/assets`. Xcode signs only when a file it copied or linked
  changed, so the first version left the app with "a sealed resource is missing or invalid"
  (`codesign --verify --deep --strict`) after an assets-only change; the script now signs again when it copied
  something, with Xcode's `EXPANDED_CODE_SIGN_IDENTITY` and the target's `.xcent` entitlements, as Xcode's own
  `CodeSign` step does. `tools/package_demo.sh` no longer builds `quench_demo_assets` in a separate `xcodebuild`
  first (it still compares the app's `assets/` with the merged folder).
