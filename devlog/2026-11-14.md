# Devlog — 2026-11-14 (Saturday)

## Goal of the day

The user's request (through the Outpost game's assistant): a live, full-duplex spoken conversation with OpenAI's
newest model, GPT-Live (`gpt-live-1`), so that the player simply talks to the station: it listens all the time,
answers by voice, can be interrupted and operates the game through the same tools as the turn-based assistant
(about 4 s a turn today). Worked in a separate worktree on the branch `live-session` from `cafa675`; nothing
committed.

## Stages

- **00:50 — The API read.** The research notes of the same night and the raw copies of OpenAI's pages (the Live
  guides, the delegation and prompting guides, the WebSocket guide, the primary WebSocket reference) and Apple's
  NSURLSession header. Every event name and field in the code comes from those pages; where they are silent the code
  and `docs/live.md` say so.
- **00:58 — WebSocket in `quench_net`** (`include/quench/net/WebSocket.h`, `FakeWebSocket.h`; `src/net/WebSocket.cpp`,
  `WsBackend.h`, `FakeWebSocket.cpp`, `AppleWebSocket.m` and `.cpp`, `NoneWebSocket.cpp`, `AppleErrors.h`). One
  connection per object, whole text and binary messages, pings, closes with codes, states, `WsEnd` with the HTTP
  status of a refused upgrade, handlers from `update()` only; wss only except loopback, header values and messages
  never logged, a message limit set as the task's `maximumMessageSize`. NSURLSessionWebSocketTask on Apple platforms;
  none elsewhere, the browser included (a browser's WebSocket cannot send an Authorization header). The local test
  server (`tests/net/net_test_server.py`) also speaks WebSocket now (RFC 6455 framing with the standard library, about
  130 lines). Two NSURLSession behaviours seen and mapped: the size limit fails with POSIX `EMSGSIZE` (40) →
  `TooLarge`; a TCP close without a close frame with POSIX `ENOTCONN` (57) → `NoNetwork`.
- **01:08 — The microphone's streaming mode and `audio::VoiceStream`.** `MicDesc::stream`: the resampled samples go
  to `takeStream()` while it records, no length limit, a bounded buffer, a mute that sends silence and keeps the
  input open. `VoiceStream`: a generator with an 80 ms jitter buffer, fades at underruns, starts and flushes, a short
  last piece played after waiting, level, audible, the played position.
- **01:12 — `assistant::LiveSession`** (`include/quench/assistant/Live.h`, `src/assistant/Live.cpp`;
  `ToolRegistry::responsesTools()`, `base64Decode()`). `session.start` with Responses delegation and the registry's
  tools, the docs' delegation-policy template appended to the instructions, tool calls from `response.event` /
  `response.output_item.done` run one per update with the schema check, `response.item.create` per call and one
  `response.create` per response once all are answered, transcripts into turns, the three appends (queued while
  starting), the uplink gate, the idle close, the reconnect at expiry (and before it at a quiet moment) with the text
  history and a state summary, usage and cost, cancel. 61 `assistant.*` cases with the fake server.
- **01:17 — The manual check against the real service** (`examples/live_check`, `quench-live-check`). The questions
  made with macOS's `say` (Samantha, and Milena for Russian) as 24 kHz WAV files, fed through the fake microphone
  in its streaming mode at real-time pace. The key loaded from the game's `.env` into the one command's environment
  by a few lines of Python, never printed. Four sessions.
- **01:20 — Fix after the first run: the server sends audio all the time.** 100 ms pieces at real-time pace for the
  whole session, zeros between answers: the session had counted silence as the station speaking (the idle close
  would never come, `Speaking` all the time). Now only pieces above about -54 dBFS count; `VoiceStream::audible()`
  (not `active()`) is the playback signal. A case for it.
- **01:24 — Gates**, then the docs (`docs/live.md` new; `docs/net.md`, `docs/audio.md`, `docs/assistant.md`, the
  index, the roadmap, `AGENTS.md`, the game skill with a short example).

## Problems and solutions

- **Silence that looked like speech.** GPT-Live streams silence as audio between answers (not documented). The
  first run showed `Speaking` from the first second. Solution above: a peak threshold per piece.
- **A reconnect inside the socket's own handler.** `session.closed` arrives inside `WebSocket::update()`, where a new
  `connect()` is refused while the old end is pending. The new session starts from the next `LiveSession::update()`,
  on a new `WebSocket` object for each session.

## Limitations and open questions

- Not run: iOS (the WebSocket backend is the same NSURLSession code), a real microphone into a session,
  loudspeakers and their echo, sessions longer than 30 s, the idle close, the expiry and the reconnect against the
  real service (only with the fake), parallel calls from the real backend, a browser (no WebSocket backend there;
  GPT-Live's browser path is WebRTC). Nobody listened to `VoiceStream` or to the answers' WAV files (they are in the
  agent's scratch directory, not in the repository).
- With the uplink gate on (the default, for loudspeakers) the player cannot interrupt the station; barge-in needs
  echo cancellation, which the engine's capture does not have.
- The documentation is silent on: the session's duration limit on a WebSocket (seen: two hours), how audio is paced
  (seen: real time, silence included), what an interruption looks like (seen: nothing but silence), the error codes
  of a refused model or tier (the start-error mapping guesses from the code's words), whether `response.completed`
  always comes for a response with function calls (it did every time; the session waits for it before
  `response.create`, with no fallback timer).
- `tools/check.sh quick` reports that the change touches the build (CMake files): `full` and `step xcode` were not
  run here (the user's decision for this task: no full, no sanitizers, no iOS, no debug build here).

## The assistant's additions for a game's own turns (entry at 02:46)

Outpost's worker found three things missing in the turn-based assistant for "callbacks" (the game starts a turn when
something happens); added on this branch so that they ship with 0.19.0. Details in [Assistant](../docs/assistant.md).

### Stages

- **Turns the game starts**: `AskOptions::source = InputSource::Event` marks the input `Game event (not the
  player):` (renamable with `setEventHeading`) in the request and the history; `AskOptions::maxRounds` and
  `maxActions` (calls of tools not marked read-only; over the cap refused to the model with the reason).
- **Cached tokens**: `Usage::cachedTokens` and `cacheWriteTokens` from `prompt_tokens_details` (OpenRouter's "Usage
  Accounting" page), in the stats, totals and the round's log line. The body's keys were the map's alphabetical
  order (`messages` before `tools`); now `model`, the settings, `tools`, `messages` (system prompt first), and
  `tool_choice` last. `ProviderSettings::cacheMarker` (off) writes Anthropic's `cache_control` on the system prompt.
- **The history by a token budget**: `Limits::historyTokens` 6000 (3 characters a token) instead of 6 turns; the
  newest turn kept uncut, older tool results cut with the whole count kept, old event turns compacted; 0.18.0's saves
  load.
- Two requests to OpenRouter (`anthropic/claude-haiku-5.5`, a 7048-token prompt with the marker, about 0.001 US
  dollars): the first wrote 7032 tokens to the cache (`cache_write_tokens`), the second read them (`cached_tokens`
  7032) at a twelfth of the price.
