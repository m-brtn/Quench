# Devlog — 2026-11-04 (Wednesday)

## Goal of the day

Decide whether the engine copied between TrailForge and Ashfall can become a standalone engine in this (empty)
repository that both games then use, and agree on the name, the scope and the target platforms.

## Stages

- **23:04 — Analysis of the two games.** Read TrailForge (`0188a3a`) and Ashfall (`2d5db57`; engine copied from
  TrailForge on 2026-11-02). Shared and identical apart from names: the shader compiler and its CMake, shader blob
  embedding, `FixedStepClock`, `GpuTimingMetal.m`; `PhysicsWorld` nearly so. Diverged: `Renderer.cpp` (Ashfall 1158
  lines, TrailForge 3301), `scene.hlsl` (2069, 4411), `Application.cpp` (1224, 3307). Conclusion: no clean engine
  layer to copy; build the engine in layers. Full inventory: `docs/migration.md`.
- **23:04 — Decisions with the user.** Name **Quench** (namespace `quench`, CMake prefix `QUENCH_`, shader guards
  `QUENCH_ENTRY_<name>`; the games keep `tf` and `af`); a GitHub repository search for "quench engine" returned
  nothing, while Forge (The Forge by Confetti), Anvil and Cinder are taken. Games consume the
  engine through FetchContent at a pinned commit with a local override (`FETCHCONTENT_SOURCE_DIR_QUENCH`). First
  iteration: phases 1 to 3 (shared infrastructure, GPU layer, app shell). The engine repository will be public on
  GitHub.
- **23:30 — Universal engine and platforms.** The user wants to bootstrap different games and eventually support
  macOS, Windows, Linux, iOS, Android and the web. Checked in SDL: SDL 3.4.18 GPU backends are Metal, Vulkan and
  D3D12; WebGPU exists only as the open experimental pull request libsdl-org/SDL#16020; the Vulkan backend rejects
  devices lacking seven Vulkan 1.0 features (`VULKAN_INTERNAL_IsDeviceSuitable`). Decision: macOS and iOS now (the user
  has a Mac with an Apple M4 Pro and an iPhone 18 Pro Max), the other platforms later; the renderer becomes a standard
  frame built from modules.
- **23:53 — User report: TrailForge plays well on the user's iPhone.** TrailForge's `AGENTS.md` still says the device
  build has never run on a real iPhone; to be corrected in that repository.
- **23:54 — Question about the "SDL GPU only" rule** of both games. Explained: it exists to keep one portable backend
  and no own abstraction layer. Continued on 2026-11-05.

## Problems and solutions

- **`sysctl` was not permitted in the sandbox.** Used `system_profiler` to identify the Mac's chip (Apple M4 Pro).
- **`gh search issues` with multi-word queries returned nothing.** Simpler queries with `--include-prs` found the
  relevant SDL issues.
- **Two wrong statements made in the chat and corrected there:** the games have no Metal or Vulkan backends of their
  own (only SDL GPU), and both are C++20, not C++17.
