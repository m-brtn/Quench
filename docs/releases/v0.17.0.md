# Quench 0.17.0

2026-11-13. Deferred assets: a web page can leave large files out of the package it loads before the first frame
and fetch them while the program runs. Asked for by the user for Outpost, whose page loaded 87 MB before its first
frame, 66 MB of it music; with its music deferred the page needs 21 MB before the first frame and the music comes
while the game runs. Changes since [0.16.0](v0.16.0.md). Source only.

**Checked in headless Chrome on the Mac only.** No other browser, no phone, no slow or broken connection has run it.

## What changed

- **CMake** (`cmake/QuenchGame.cmake`, `cmake/StageAssets.cmake`; [Assets](../assets.md#deferred-assets)).
  `quench_add_game(... DEFERRED_ASSETS <pattern>...)`: a file, a directory or a `file(GLOB)` expression relative to
  the asset root. In a web build the matching files are left out of the page's `<OUTPUT_NAME>.data` package and
  copied beside the page to `<OUTPUT_NAME>.assets/<path>`; their list (a size and a path each) is packed at
  `/quench/deferred_assets.txt`. Files that become deferred are removed from the stage if an earlier build put them
  there, and files no longer deferred are removed from the folder. A pattern that matches nothing is a build
  warning. Every other platform ignores the option: the files are in the bundle as all others.
- **Staging** (all builds): Finder's `.DS_Store` files are kept out of the staged assets (and one an earlier build
  staged is removed); a file two asset sources share is staged once, from the later source (before, both copies ran
  each time). In a web build the two `--preload-file` flags are `SHELL:` flags (CMake merged two plain ones into one
  and the link failed).
- **API** (`include/quench/core/FileSystem.h`). `enum class fs::AssetState { Missing, Present, Deferred, Fetching,
  Failed }`, `fs::assetState(path)` and `fs::requestAsset(path, priority = 0)`; both are also virtual functions of
  `fs::Backend` with defaults (a file that exists is `Present`, anything else `Missing`; a request does nothing),
  forwarded by the asset overlay. Neither waits.
- **The browser** (`src/app/SdlFileSystem.cpp`). The list is read when the file system is created. A request queues
  the file; at most two downloads run at a time (`emscripten_async_wget2`: XMLHttpRequest, written into the virtual
  file system at the asset root when complete, its callbacks on the main thread between frames, no Asyncify), the
  highest priority first and in the order asked among equal ones; asking again raises a waiting file's priority. A
  failed download is tried once more, then the file is `Failed` for the session with a warning. From its arrival a
  file is read like a packed one (`readAsset`, `openAsset`, a music stream). The log has one line per file, as
  `assets: fetched deferred/greeting.txt (85 B, 8 ms)`.
- **Scenarios** (`src/app/AppScenario.cpp`): the command `asset_request PATH [PRIORITY]`, the values
  `asset_state:PATH` (0 to 4) and `asset_size:PATH` (the bytes `fs::readAsset` reads, -1 when it cannot).
- **Tools.** `tools/web_check.mjs --not-found PATH` answers that file with 404 and counts the answers.
  `tools/check.sh step web` checks hello's deferred files (below). `tools/publish_web.sh` copies the pages'
  `<name>.assets/` folders (today `hello.assets/`) into the site.
- **The sample** `hello` has `ASSETS assets` with `DEFERRED_ASSETS deferred`: two small text files, beside the page
  in a web build and in the bundle everywhere else. Core test `fs_asset_state` (the default backend and the overlay).
- **Docs and skill:** [Assets](../assets.md#deferred-assets), [App shell](../app.md),
  [Platforms](../platforms.md#web-webassembly), and the `quench-game` skill (`SKILL.md`, `reference.md`).

## What was not verified

- Any browser but headless Chrome on the Mac; a phone; a slow, stalled or broken connection.

- Outpost's use of it (built, never run).

## Known gaps

- No timeout of the engine's own: a stalled download stays `Fetching` until the browser gives up.
- A fetched file stays in the browser's memory for the session (the in-memory file system, as packed files do).
- Nothing is kept between visits by the engine; only the browser's HTTP cache may keep the files.
- No progress in bytes in the API.
- An `AssetManager` load of a file that has not arrived fails like any missing file: a game checks
  `fs::assetState` first.
- Downloads continue while the tab is in the background.

## Changes for games

Nothing has to change in a game's code or build: without `DEFERRED_ASSETS` a game builds and runs as before.

- **Deferring assets.** List the files in `quench_add_game(... DEFERRED_ASSETS <pattern>...)` (relative to the asset
  root). Ask for them early with `fs::requestAsset(path, priority)` and use a file only once
  `fs::assetState(path)` is `fs::AssetState::Present`; never wait for it. On the desktop and iOS the files are in
  the bundle and `Present` from the start, so the same code runs everywhere.
- **Publishing.** A game's publishing script must copy the `<OUTPUT_NAME>.assets/` folder beside the page, next to
  its `.html`, `.js`, `.wasm` and `.data` files; without it the deferred files end `Failed`.
- **`fs::Backend`** has two new virtual functions, `assetState` and `requestAsset`, with defaults: a game's own
  backend compiles unchanged.
- **Staging:** `.DS_Store` files are no longer staged; a file two asset sources share is staged once, from the later
  source (the same result as before, one copy less).
- A game gets this by moving its engine pin to this release and copying the `quench-game` skill again.

TrailForge (pinned `d708783`) and Ashfall (its own code) are not affected until they move.
