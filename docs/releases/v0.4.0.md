# Quench 0.4.0

2026-11-05. Stage 6 of the [roadmap](../roadmap.md): the job system, the asset system and the asset cooker, except
shader hot reload. Source only. Changes since [0.3.0](v0.3.0.md) (tag `v0.3.0`).

## What changed

- **Job system** ([Jobs, assets and the cook](../assets.md#job-system)). `quench::JobSystem` in `quench_core`, on
  enkiTS: one pool for the engine and the game, jobs with dependencies and priorities (`JobPriority`), `run()`,
  `parallelFor()`, `wait()` (runs queued jobs meanwhile), `waitAll()` and `runFor()`. Without worker threads (the
  single-threaded web build, `--worker-threads 0`) jobs run on the frame thread across frames. Every worker raises its
  priority through `raiseWorkerThreadPriority()`. The app owns one (`App::jobs()`), with hardware threads - 1 workers
  by default (at most 15).
- **Physics on the job system.** `PhysicsWorld` runs Jolt's jobs on a `JobSystem` through a
  `JPH::JobSystemWithBarrier`; without one it steps on the calling thread. Jolt's own thread pool is no longer used.
  The demo's physics capture is byte-identical with Jolt's old pool, with one thread and with the job system.
- **`quench_assets`** ([Assets](../assets.md#assets)), headless. `AssetId` (XXH64 of the path), reference-counted
  `AssetRef<T>`, and `AssetManager`: a cache by ID, asset types registered by the modules that use them, reads
  through `quench::fs` and decodes on jobs, placeholders while loading and on failure (an error and a log line, never
  a crash), memory budgets per type with LRU eviction of unreferenced assets, a per-frame upload budget and a time
  budget for the jobs the frame thread runs without workers, priorities, reloads, simulated latency for tests. KTX2
  textures (`TextureImage`, a CPU BC7 decoder for devices without BC sampling) and cooked `.qmodel` models
  (meshoptimizer streams, LODs, materials). `StreamingGrid`: cells load and unload around focus points with
  hysteresis, nearest first. The app owns one manager (`App::assets()`), updated every frame before `Game::update`.
- **Hot reload of assets on the Mac.** With `--hot-reload` or `AssetManager::setHotReload()`, a changed file in the
  asset directory is loaded again in place; a failed reload keeps the loaded data. Needs `fs::Backend::modifiedTime()`
  (the standard library and the SDL backends have it).
- **Assets in the scene.** `render::SceneAssets` loads textures (`TextureAsset`: white while loading, a magenta
  checker on failure) and models (`ModelAsset`, placed with `addModel()`: a gray box while loading, a magenta box on
  failure, rebuilt after a reload) into the retained scene.
- **`quench_cook`** ([quench_cook](../assets.md#quench_cook)), a host tool: glTF and GLB (fastgltf), PNG and JPEG
  (stb_image) and KTX2 in; KTX2 textures out (BC7 where the size allows, else RGBA8; mipmaps filtered in linear light;
  block rows encoded in parallel) and `.qmodel` models (primitives merged per material, meshoptimizer vertex cache
  and fetch order, LODs by simplification, quantized and encoded streams) with their textures. The output is
  byte-identical for any number of workers; a depfile per asset. In CMake: `quench_cook_assets()` and
  `quench_add_game(... COOKED_ASSETS ...)` (cooked files merged into the game's assets on macOS and iOS); cross builds
  take a host `quench_cook` through `QUENCH_HOST_COOK` (the `host-tools` preset builds it, the iOS presets pass it).
- **Engine demo** ([Engine demo](../demo.md)). An eighth section, "Assets": five cooked models (a glTF with an
  external buffer and PNG, a GLB with embedded JPEG and PNG, a glTF with a data URI and vertex colors, a broken and a
  missing file) and a streaming grid of tiles with eight cooked BC7 textures around a moving focus, with load stats,
  latency, cache and upload budgets, reload and hot reload. Its sources are procedural (CC0). Scripted check and
  golden captures for Metal and Vulkan through MoltenVK; the other sections' goldens differ from 0.3.0 only in the
  menu's new line.
- **Fix found by the web check.** A corrupt KTX2 header could ask for gigabytes; such files are rejected now (test
  `assets.ktx2_rejects_corrupt`).

  Assets section and its benchmark there.

## Changes for games

What a game on 0.3.0 changes or checks when it moves to 0.4.0:

- **`PhysicsWorld` takes a job system.** `PhysicsWorld(JobSystem* jobs)` and `PhysicsWorld(JobSystem* jobs, const
  Settings&)` replace `PhysicsWorld()` and `PhysicsWorld(const Settings&)`. Pass `&app.jobs()` (or a game's own
  `JobSystem`) to step on worker threads, `nullptr` to step on the calling thread. `Settings::workerThreads` is
  replaced by `Settings::maxConcurrency` (threads working on one step at most; -1: the job system's threads, at most
  5).
- **The app starts a job system and an asset manager** before `Game::init` and destroys them after the game: a game
  process has hardware threads - 1 worker threads by default. `--worker-threads`, `--asset-latency` and
  `--hot-reload` are engine flags now (consumed before `createGame()`): a game flag of the same name is renamed.
- The log has a new `jobs: job system: N worker threads` line at the start, and `assets:` lines for failed loads and
  reloads; tools that read the log skip them.
- `fs::Backend` has a new virtual `modifiedTime()` with a default that returns nothing: a game's own backend compiles
  unchanged and has no hot reload. New: `fs::assetModifiedTime()`.
- `render::Scene`: new `addTexture(const assets::TextureImage&, name)`, `addEmptyTexture()` (samples as white until
  filled), `setTexture()`, `meshUsers()` and `materialUsers()`; new handle `ModelInstanceId`. `Scene.h` and `App.h`
  now include `quench_assets` headers, and `quench_app` and `quench_render` link `quench_assets`.
- New and optional: `quench_assets`, `render::SceneAssets`, `quench_cook_assets()` and `quench_add_game(...
  COOKED_ASSETS ...)`. A cross build that cooks assets needs `QUENCH_HOST_COOK`.
- Every configure for the host now also downloads enkiTS, xxHash, meshoptimizer and bc7enc_rdo (runtime) and
  fastgltf, simdjson, simdutf and stb (the cooker), also when nothing is cooked; the cooker is built only where
  something cooks. Pins and licences: [Dependencies](../dependencies.md).
- A game moves its FetchContent pin to the commit of `v0.4.0`.

## Known limitations

- **Shader hot reload is not done** (P1 in the roadmap, stage 6 remaining work); only asset files reload, and only
  where the asset directory is a directory of the file system (the Mac). Hot reload on a device needs an asset server
  (later).
- The cook writes BC7 and RGBA8 only: ASTC and Basis Universal (needed for Android and the web) are not done; a device
  without BC sampling gets BC7 decoded to RGBA8 on the CPU (four times the memory).
- The standard surface reads only base color textures: normal and emissive textures are cooked but not used (no normal
  maps in `quench_render`); occlusion textures, `KHR_texture_transform`, unlit materials, skins, morph targets,
  cameras and lights of glTF files are not cooked.
- Streaming has no memory budget across cells beyond the per-type budgets of unreferenced assets.
- Loads finish in real time, so a scripted capture that depends on when a load finished is not byte-identical with
  TAA (the demo's assets check uses FXAA).
- Not run on the iPhone (see "What was verified"). No audio or animation (stages 7 and 8). Only one GPU backend (SDL
  GPU). The demo's macOS package is signed ad hoc and not notarized; its iOS package is development-signed and runs
  only on the devices of its profile. Windows, Linux, Android and browsers have not been run.
