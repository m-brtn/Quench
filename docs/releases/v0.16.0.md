# Quench 0.16.0

2026-11-13. The user files of a browser build are kept: a game's default user directory (its settings, its saves)
is stored in the browser's IndexedDB and is there again after a reload and at a later visit of the page, with no
change in the game's code. Asked for after Outpost 0.2.0 got a saved game that a reload of its page lost (the
user's request: "make the save on the web survive a page reload"). Changes since [0.15.0](v0.15.0.md). Source only.

**Checked in headless Chrome on the Mac only.** No other browser, no phone and no private window has run it.

## What changed

- **The engine** (`src/app/SdlFileSystem.cpp`; [App shell](../app.md#web-runs), "User files in a browser").
  In a web build the default user directory, SDL's `/libsdl/<organization>/<name>/`, is backed by Emscripten's
  IDBFS, mounted at that directory: the IndexedDB database is named after it (`/libsdl/<organization>/<name>`),
  one per app, so the pages of one origin (all of a GitHub Pages account) keep their files apart.
  - Loaded before the first read: when the file system is created (in `SDL_AppInit`, before the game's `init`)
    the app waits for the stored files through Asyncify, at most 5 s (`kUserFilesLoadTimeoutMs`).
  - Stored after each write: every successful `fs::writeUser` starts a store of the directory in the background,
    one at a time; a write during a store starts one more when it ends.
  - Without IndexedDB (none in the context, storage disabled, an error, no answer within 5 s) the directory stays
    in memory as before and the log says once why; a store that fails later is one warning, and the write has
    succeeded.
  - What `--user-dir` names stays in memory, so scripted checks start empty. Desktop, iOS and the `wasm-node`
    build are unchanged (the code is compiled for browser builds only).
  - The page's script can read the state as `Module.quenchUserFiles`.
- **The page check tool** (`tools/web_check.mjs`): several argument lists separated by `--` load the page one
  after another in the same browser profile; `--system-user-dir` leaves out the `--user-dir /user` it adds
  otherwise; `--databases N,N,...` is the number of IndexedDB databases the origin must have after each load
  (after the program's stores have ended). A run with one argument list is as before: one load, a fresh profile.
- **`tools/check.sh step web`** loads the demo three times in one profile: with `--user-dir /user` and
  `settings_save.txt` (no database afterwards), in the default user directory with `settings_save.txt` (it starts
  without settings: nothing was left behind; one database), then `settings_load.txt` (the settings read back
  through `quench::fs`; still one database). About 4 s.

## What was not verified

- Safari, Firefox, a phone's browser, a private window, storage disabled, a quota error.
- The paths without IndexedDB, after an error and after the 5 s limit were read in the code, not run.

## Known gaps

- Files written in the moment before a tab closes are lost if their store had not ended (there is no store when
  the page is hidden or closed).
- Two tabs of one game share its database; each stores its whole directory, so a store of one can overwrite or
  remove the other's newer files.
- IndexedDB is best-effort storage: the browser may evict it, and clearing the site's data removes it (the engine
  does not ask for persistent storage).
- If IndexedDB answers after the 5 s limit while the stored files are being copied in (not while it is opened),
  the copy still writes them into the in-memory directory.
- Every store compares the whole user directory with the database (cheap for a save and a settings file; captures
  in the user directory are stored too).

## Deployed

The web demo at <https://m-brtn.github.io/Quench/> is published from the tagged commit by `tools/publish_web.sh
--no-build --push` after `tools/check.sh step web` passes on that commit; the published page's `version.txt`
names 0.16.0 and the tagged commit. The result is in the [2026-11-13 devlog](../../devlog/2026-11-13.md).

## Changes for games

Nothing has to change in a game's code. A game gets this by moving its engine pin to this release; its next web
build keeps its default user directory between visits.

- Programs that link `quench_app` in a web build now also link `-lidbfs.js` through it (Emscripten's IDBFS).
- In a web build, startup can wait up to 5 s for IndexedDB before the game's `init`.
- Scripted checks that use the default user directory in a browser (no `--user-dir`) now see the files of earlier
  runs in the same browser profile; `tools/web_check.mjs` still adds `--user-dir /user` unless told otherwise.

TrailForge (pinned `d708783`) and Ashfall (its own code) are not affected until they move.
