# Quench 0.18.0

2026-11-13. The foundation of an in-game assistant: HTTPS requests, microphone capture and a module that lets a
language model operate a game through tools the game registers. Asked for by the user for Outpost: a player enters
their own API key in the game's settings, types or says what they want ("send walker one to the nearest cell"), and
the model calls the game's tools, the game carries them out, and the model answers in text and, optionally, speech.
Changes since [0.17.0](v0.17.0.md). Source only.

**Against a real provider only from the Mac, through NSURLSession.** The web's fetch backend, an iPhone, Safari and
Firefox have not talked to a provider; the iOS code ran only in the iOS Simulator's tests.

## What changed

- **`quench_net`** (new library, headless; `include/quench/net/Http.h`, `FakeNetwork.h`; [Network](../net.md)).
  Asynchronous HTTP requests: `net::Client` with `send(Request, Handlers)` (a `RequestId`, or an error at once),
  `cancel`, `cancelAll` and `update()` once a frame; `Request` (method, URL, headers, body, `timeoutSeconds` 30,
  `maxResponseBytes` 16 MB, `streamBody`), `Response` (status, headers, body, bytes, seconds, an `ErrorKind` and a
  message). The handlers (`onHeaders`, `onChunk` for each piece of a streamed body, `onDone` exactly once, also after
  a cancel) are called from `update()` on the main thread only. Backends: NSURLSession on macOS and iOS (an
  ephemeral session: no cookies, cache or stored credentials; its delegate on a serial background queue hands
  events to the main thread through a locked queue), the browser's fetch in web builds (AbortController, a stream
  reader), none on Linux, Windows and under Node.js (a send fails at once), and `net::FakeNetwork` for tests
  (programmed answers, chunks over time, failures). The rules: HTTPS only, except `localhost`, `127.0.0.1` and
  `[::1]`; no credentials in a URL; at most 5 redirects, each target under the same rule, the secret headers
  (Authorization, Cookie and names with key, token, secret, password or session) dropped on a redirect to another
  origin; no cookies; the size limit enforced while the body arrives; the log shows method, host, path, status,
  bytes and milliseconds, never a header's value, a body or a query string.
- **Microphone capture** (`include/quench/audio/Microphone.h` in `quench_audio`, the device in
  `quench_audio_device`; [Audio](../audio.md#microphone)). `audio::Microphone`: `permission()` (`Unknown`,
  `NotAsked`, `Asking`, `Granted`, `Denied`, `Unavailable`) and `requestPermission()`; states (idle, opening,
  recording, finished, failed); `start(MicDesc)` (8 to 48 kHz, 16 kHz by default; a length limit up to 600 s, 30 s
  by default), `stop`, `cancel`, `level()` for a meter, `seconds()`, `takeRecording()` (mono float, `pcm16()`,
  `wav()`). The device's thread only writes a lock-free ring; the main thread drains it, resamples and cuts at the
  limit. The permission through AVFoundation on macOS and iOS (on iOS the audio session switches to
  `PlayAndRecord` while recording and back), `getUserMedia` in a browser. `App::microphone()`, updated before
  `Game::update`; a recording stops when the app goes to the background. `quench_add_game(... MICROPHONE
  "reason")`: the reason becomes the iOS `NSMicrophoneUsageDescription` and is declared to the engine before
  `main`; without it a request and a start fail with an error that names the option. The fake source plays fed
  samples: scripted runs (`--script`, `--capture`, `--quit-after`) use it and never open a device or ask; `--microphone
  device|fake`; scenario commands `mic_permission`, `mic_request`, `mic_start`, `mic_stop`, `mic_cancel`,
  `mic_feed`, `mic_tone`, `mic_clear`, `mic_take` and the `mic_*` values. `audio::encodeWavPcm16`. A manual check:
  `hello --mic-check SECONDS`.
- **`quench_assistant`** (new library, headless, on `quench_net`; `include/quench/assistant/`;
  [Assistant](../assistant.md)). A client for OpenAI-compatible APIs. `ProviderSettings` (base URL, key, the chat,
  transcription and speech models, voice, formats, timeouts, streaming, extra headers) with presets
  `openRouterPreset()`, `openAiPreset()` and `localPreset(url)`; `settingsToJson` saves everything but the key.
  Tools in MCP's shape: `ToolRegistry` with `Tool` (name, description, `inputSchema`, MCP's annotations, a handler),
  `list()` and `callResult()` as MCP's `tools/list` and `tools/call` results, a JSON Schema check before a handler
  runs, bad calls returned to the model as error results. The turn: `Assistant::ask(text)` sends the history, the
  game's state summary and the tools; the model's tool calls run one per `update()` on the main thread, up to 3
  rounds (the last sends `tool_choice: "none"`), then the answer; `cancel()` at any point; one operation at a time
  (a second is refused as busy); a bounded history; events, counters and the usage (OpenRouter's cost when given).
  The streamed answer is parsed incrementally (server-sent events cut anywhere, or one JSON body). Speech-to-text
  (`transcribe`: JSON with base64 audio or a multipart form) and text-to-speech (`speak`: PCM, or MP3 decoded by the
  engine); `askByVoice(wav)` transcribes, asks and speaks in one call. Errors are kinds with the provider's own
  message, the key redacted. A manual check program, `examples/assistant_check/` (macOS, no window, the key from
  `OPENROUTER_API_KEY` only).
- **JSON** (`quench::json`, `src/core/Json.cpp`). A `\u` surrogate pair (`"\ud83d\ude00"`, what a server that escapes
  non-ASCII sends for an emoji) now decodes to one code point in four UTF-8 bytes; before, each half became a
  three-byte sequence, which is not valid UTF-8. A lone surrogate becomes U+FFFD. A `\u` without four hex digits is now
  a parse error (it was read up to the first non-digit). The writer is unchanged: it escapes only `"`, `\` and the
  control characters, so text outside the Basic Multilingual Plane is written as UTF-8 and reads back the same. The
  assistant's own repair of pairs is gone.
- **`quench_add_game()`** links `quench_net` and `quench_assistant` into every game, beside `quench_main`, and has the
  `MICROPHONE` option. `tools/check.sh` has the labels `net` and `assistant`; `step web` adds hello's network check
  and a recording through Chrome's fake microphone. The `quench-game` skill has sections on HTTP requests, the
  microphone and the assistant; `tools/check_skill.py` checks names after `net::` and `assistant::`.
- **Docs:** [Network](../net.md), [Assistant](../assistant.md), [Audio](../audio.md#microphone),
  [App shell](../app.md), [Platforms](../platforms.md), and the skill (`SKILL.md`, `reference.md`).

## What was not verified

- An iPhone: the record permission, the audio session's switch to `PlayAndRecord` and back, interruptions,
  NSURLSession on a mobile network, the iOS device test app.
- Safari and Firefox (the microphone's `getUserMedia` path and fetch with a real provider's CORS).
- A real provider through the web's fetch backend; OpenAI's own API (the preset's model names unchecked); a local
  server; proxies and captive portals.
- Windows and Linux with the microphone (not built with it); the `headless` preset.

## Known gaps

- No WebSocket and no live speech-to-speech; speech is whole files, not streamed playback.
- No MCP transport: the tools have MCP's shape, but no MCP server or client is there.
- No OAuth sign-in. Keeping the player's key is the game's business (`settingsToJson` leaves it out).
- No backend for HTTP on Windows, Linux or Android yet; no device selection, echo cancellation or voice activity
  detection for the microphone.
- On iOS miniaudio's null backend paces itself by whole seconds: with `MAC_OS_X_VERSION_MIN_REQUIRED` undefined there,
  the pinned miniaudio picks its old `mach_absolute_time` timer, which divides integers. Only the null backend (tests,
  `--audio-device null`) is affected; Core Audio paces the real devices. Not patched (no pin change).
- In a browser the microphone runs on a `ScriptProcessorNode` on the page's main thread (a deprecated API).
- The macOS linker notes "ignoring duplicate libraries: 'libquench_net.a'" when it links a game or the demo
  (`quench_assistant` brings `quench_net` again); harmless, new in this release.
- A handler's exception aborts in web builds (exceptions are not caught there); handlers return error results.

## Changes for games

Nothing has to change in a game's code or build: a game that uses none of this builds and runs as before.

- **Linking.** Every game now links `quench_net` and `quench_assistant` through `quench_add_game()`; nothing to add.
- **HTTP requests.** Keep a `net::Client`, call its `update()` once a frame and `send()` requests with handlers; the
  handlers run on the main thread. HTTPS only, except a local server. [Network](../net.md).
- **Microphone.** Add `quench_add_game(... MICROPHONE "the reason shown to the player")`, then use
  `app.microphone()`: ask for the permission, `start`, `stop`, `takeRecording()`. Scripted runs use the fake source.
  [Audio](../audio.md#microphone).
- **Assistant.** Keep an `assistant::Assistant`, call its `update()` once a frame, set its settings (the player's
  key from the game's settings UI) and register the game's tools; then `ask()` or `askByVoice()`.
  [Assistant](../assistant.md).
- **JSON behaviour.** `json::parse` now gives U+FFFD for a lone surrogate escape and refuses a `\u` without four hex
  digits (before: two invalid three-byte sequences for a pair, and a half-read escape). A game that relied on the
  old bytes, or reads files with malformed escapes, sees the difference.
- A game gets this by moving its engine pin to this release and copying the `quench-game` skill again.

TrailForge (pinned `d708783`) and Ashfall (its own code) are not affected until they move.
