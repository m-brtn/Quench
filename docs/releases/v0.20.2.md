# Quench 0.20.2

2026-11-15. One fix in `quench_ui`, found by the user with the Mac package of the demo: some clicks on its buttons
were lost. Changes since [0.20.1](v0.20.1.md). Source only.

Released without the full gate, by the user's decision, as 0.20.0 and 0.20.1 were.

## What changed

- **`quench_ui` lost clicks whose press and release arrive in one frame.** `ui::Ui::begin` took the press and the
  release from the mouse button's level in two successive frames. A click whose two halves arrive within one frame
  (a tap on a trackpad, on a display of 120 frames a second) was never "down" in any frame, so a button did not
  fire: in the demo's Game UI section on the Mac "Next line" sometimes did nothing and "Hurt" seemed late (the
  first click lost, the second taken), while the web build, where a browser hands events over frame by frame, was
  fine. The module now reads the frame's edges.
- **`app::Input::mouseReleased(button)`**: the button went up this frame, beside `mousePressed`. The input kept
  both edges already; only the first could be read.

## Changes for games

None to make. A game that reads clicks from `mouseDown` in two frames has the same defect: read `mousePressed` and
`mouseReleased`.

## What was verified

On the Mac (Apple M4 Pro), Release: the new case `app.input_mouse_click_within_one_frame` (a press and a release in
one frame: not down at its end, pressed and released in it, both edges gone in the next) with the five other input
cases, 6 of 6; the demo's `scenarios/hud.txt`, 31 of 31; the Mac package's smoke run, 27 of 27. The user tried a
package of this code on the Mac and asked for the release.

## What was not verified

- The lost click was not reproduced by a test of the module itself: the cause was read from the code, and the
  scenarios' clicks span two frames. The input's edges are tested; the module's use of them is not, except by the
  user's hand.
- The gate was not run (no `tools/check.sh`, Debug, sanitizers, iOS, `step web`); the demo's batches were not run
  again for this patch.
