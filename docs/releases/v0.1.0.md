# Quench 0.1.0

2026-11-05. The first version: stages 1 to 3 of the [roadmap](../roadmap.md). Source only. No game builds on it yet;
TrailForge and Ashfall move to it in stage 4.

## What is in it

- **Build.** CMake 3.28 presets for macOS (`debug`, `release`, `asan`, `tsan`, `headless`), iOS (`host-tools`,
  `ios-sim-release`, `ios-sim-tests`, `ios-device-release`, `ios-xcode`) and the web check (`wasm-node`). Pinned
  dependencies: SDL 3.4.18, Jolt Physics 5.6.0, GLM 1.0.3, Dear ImGui 1.92.9b, and the shader toolchain
  ([Dependencies](../dependencies.md)). `-Wall -Wextra`, `-Werror` when the engine is built on its own.
- **`quench_core`.** `Result<T>`, `QUENCH_ASSERT`, `quench::log` (levels, categories, sinks), `FixedStepClock`, JSON,
  `quench::fs` (checked relative paths, read-only assets, atomic writes to the user directory), worker thread
  priority.
- **`quench_physics`.** `PhysicsWorld` on Jolt.
- **Shaders.** `quench_shaderc` compiles HLSL at build time to SPIR-V, MSL and metallib (DXIL on Windows hosts);
  `quench_add_shaders()` embeds them with the resource counts SDL GPU needs.
- **`quench_gpu`.** The GPU layer over SDL GPU: resources, pipelines, render and copy passes, uploads, downloads,
  mipmaps, blits, fences, presentation, GPU timing on Metal, `gpu::Caps`.
- **`quench_app` and `quench_main`.** The engine owns `main` (SDL main callbacks); a game implements
  `quench::app::Game`. Window and iOS lifecycle, fixed step with interpolation, input actions (keyboard, mouse,
  gamepad, touch), ImGui drawn through `quench::gpu`, common flags, deterministic scripted runs with a scenario
  language (checks, scripted input, performance regions), PNG captures ([App shell](../app.md)).
- **Games.** `quench_add_game()`: a macOS executable or an iOS app bundle with Info.plist, icon and assets (Ninja for
  the Simulator, Xcode with Automatic signing for devices). `templates/game` and `tools/new_game.py` create a new game
  that builds against a pinned engine commit.
- **Sample.** `examples/hello`: a lit mesh, ImGui, capture checks against golden images, an input scenario and a
  benchmark ([Performance](../performance.md)).

  Simulator; captures looked at.

## Changes for games

None: no game uses the engine yet. What a game changes when it moves to 0.1.0 (stage 4, [Migration](../migration.md)):

- `main` and the `while` loop go: the game implements `quench::app::Game` and `createGame()` and is built with
  `quench_add_game()`.
- Files through `quench::fs` instead of `std::ifstream` / `std::ofstream` / `fopen`.
- Shader entry guards become `QUENCH_ENTRY_<name>` / `QUENCH_STAGE_*`; shaders are registered with
  `quench_add_shaders()`; draw calls go through `quench::gpu` instead of SDL GPU.
- ImGui is set up and drawn by the engine; the game's ImGui backend code and TrailForge's ImGui iOS patch go.
- The engine's flags (`--quit-after`, `--capture`, `--script`, ...) replace the game's flags of the same purpose;
  game scenario commands move to `Game::scenarioCommand` and `Game::scenarioValue`.

## Known limitations

- No renderer yet: games draw with their own passes (stage 5). No asset pipeline, job system, audio or animation.
- Only one GPU backend (SDL GPU). GPU timing reads SDL 3.4.18's internal Metal fence; Metal only.
- On macOS, `--present-mode immediate` stays at the display rate and inflates the measured GPU time; benchmarks use
  vsync.
- Windows, Linux, Android and browsers have not been run.
