# Quench 0.2.0

2026-11-05. Stage 4 of the [roadmap](../roadmap.md) for the first game: the app shell and the GPU layer extended
for a game moving onto them. Source only. Changes since 0.1.0 (commit `c1197e9`; 0.1.0 has no tag).

## What changed

- **Scenario perf regions run in real time.** Between `perf_begin` and `perf_end` the frame time is the real frame
  time, with as many ticks per frame as in normal play, so a region measures the real frame cost;
  `App::deterministic()` is false inside. Before, a region ran one 1/120 s tick per frame like the rest of a scripted
  run.
- **Deterministic frames keep real-time pace.** A `--script` or `--capture` frame is never shorter than the fixed
  step in real time (`SDL_DelayPrecise`), so background work such as streaming keeps its pace against app time.
- **`perf:` line.** Frame p10, GPU min and p10 (values `perf_frame_p10`, `perf_gpu_min`, `perf_gpu_p10`), and the
  game's own fields at the end from the new `Game::perfDetails(App&)`.
- **`App::scripted()`**: true while a `--script` scenario runs (a game may start from defaults and keep user files
  untouched).
- **`createGame()` may return a null game without an error**: the program ends with exit code 0 before SDL starts,
  for game flags that only print. Before, it failed with "createGame returned no game".
- **Scripted key events carry the keycodes of real key events** (`SDL_GetKeyFromScancode(..., true)`): with SDL's
  default keycode options, letters stay Latin on keyboard layouts without Latin letters. Before, scripted keys took
  the current layout's keycodes.
- **ImGui.** `quench/app/ImGuiRenderer.h` is public, with `imguiTexture()`, so a program with its own window and loop
  can draw ImGui through `quench::gpu` without `App` ([App shell](../app.md#imgui)). The ImGui sampler uses Linear
  mipmaps, like ImGui's own SDL GPU backend.
- **GPU.** `ColorTarget::cycleResolve` (SDL's `cycle_resolve_texture`).
- **Sample.** hello's benchmark region runs in real time: about 600 frames at 60 Hz, 1200 at 120 Hz (the script
  expects at least 300).
- **Tools and docs.** `tools/check_games.sh` builds the games that use the engine against a local checkout, starts
  them and checks exit code 0 and a capture. [Migration](../migration.md) has notes for a game moving onto the app
  shell.

## Changes for games

Nothing is renamed or removed. What a game on 0.1.0 checks when it moves to 0.2.0:

- `App::deterministic()` is false inside a scenario's `perf_begin` .. `perf_end` region, and the region runs in real
  time: a game that hides timings in deterministic runs shows them there, and scripts that expect a frame count in a
  perf region change (it follows the display rate).
- Deterministic runs take at least one fixed step of real time per frame: on a display faster than the fixed step
  rate they take longer in wall time.
- The `perf:` line has new fields (`p10` for frames, `min` and `p10` for GPU, the game's fields after `; ` at the
  end): tools that parse it need updating.
- Scripted key events have the keycodes of real key events. A game that matches keycodes and worked around the old
  layout-dependent ones drops the workaround; bindings by scancode (`quench::app::Input`) are unaffected.
- `createGame()` returning a null game without an error now ends with 0; a game that used it as a failure returns an
  error instead.
- Images with mip levels drawn with `ImGui::Image` are sampled with Linear mipmaps; captures that show them change.
- New and optional: `Game::perfDetails`, `App::scripted`, `ColorTarget::cycleResolve`, the public
  `quench/app/ImGuiRenderer.h` (`imguiTexture()` moved there; `App.h` includes it).
- A game moves its FetchContent pin to the commit of `v0.2.0`. A game still on its own main loop: what changes when
  it moves onto the app shell is in [Migration](../migration.md).

## Known limitations

- No renderer of its own yet: games draw with their own passes (stage 5). No asset pipeline, job system, audio or
  animation.
- Only one GPU backend (SDL GPU). GPU timing reads SDL 3.4.18's internal Metal fence; Metal only.
- On macOS, `--present-mode immediate` stays at the display rate and inflates the measured GPU time; benchmarks use
  vsync. The engine has no getter for the present mode.
- No engine test covers the keycode of a scripted key event or `ColorTarget::cycleResolve`; both were checked only
  in a game.
- The benchmark's CPU times (0.1 to 0.3 ms) swing more between runs than the 5% rule can resolve.
- Windows, Linux, Android and browsers have not been run.
