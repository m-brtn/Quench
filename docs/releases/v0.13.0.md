# Quench 0.13.0

2026-11-10. Two new platforms, both early: a Windows build of the engine, the sample and the demo (SDL GPU's
Direct3D 12 and Vulkan drivers, built and tried on GitHub's runner only), and an experimental browser build on a
WebGPU backend of the engine's own, published at <https://m-brtn.github.io/Quench/>. Changes since
[0.12.1](v0.12.1.md). Source only.

Nothing in this release has run on real Windows hardware. The browser build ran in Chrome and Safari on one Mac.

## What changed

### Windows (stage 15, part 1)

- The engine, the sample, the demo and the tests build with MSVC (`/W4 /WX` for engine targets, `/utf-8`,
  `/Zc:__cplusplus`, `/Zc:preprocessor`, `/bigobj`, the static runtime) through the `windows-release` preset.
- `.github/workflows/windows.yml` builds on GitHub's `windows-2025` runner on a push to `windows-build` or by hand.
  It runs the headless tests, then the GPU, app and demo tests and a smoke run of the packaged demo on the runner's
  software adapter, and uploads the demo as an artifact. It is a build, not a gate: the engine's gates stay local.
- Fixes Windows found:
  - SDL GPU's shader blit pushes uniforms of its own into fragment slot 0. The SDL GPU backend now pushes the
    engine's again after a blit or a mipmap generation. This also fixes SDL GPU's Metal driver on the Mac.
  - SDL GPU took a mip level's size as `size >> level`, which is 0 for the last levels of a non-square texture.
    The `SdlLevelSize.cmake` patch keeps it at least 1.
  - Depfile paths are written with '/'.
  - DXC command lines are now quoted correctly for `cmd.exe`.
  - Basis Universal's Zstandard symbols are now renamed under MSVC too.
  - Two tests made Windows-proof: a file is closed before it is removed, and a thread stress test no longer relies
    on 1 ms sleeps.
  - The demo drew several random numbers inside one call's arguments, whose order differs between compilers. Each
    draw is now a statement of its own, so the scenes match on every compiler; the Mac's scenes are unchanged.

### The web (experimental)

- A `web` preset builds the engine, the sample and the demo as single-threaded WebAssembly for a browser
  (Emscripten 6.0.13, Asyncify).
- A native WebGPU backend, `src/gpu/webgpu/`, runs on Emscripten's `emdawnwebgpu` port: `gpu::Backend::WebGpu`, the
  only backend of a web build. SDL GPU 3.4.18 has no WebGPU driver; the open pull request libsdl-org/SDL#16020 was
  tried and dropped.
- Shaders: `quench_shaderc --wgsl-spirv` writes SPIR-V with the WebGPU binding layout, and Tint, built from Dawn's
  source into the tool cache, translates it to WGSL at build time (`gpu::ShaderFormat::Wgsl`). The ray query
  entries have no WGSL form, so the ray tracing effects take their fallbacks.
- `quench_add_game()` makes a page (`cmake/shell.web.html`) with the assets preloaded. Program arguments come from
  the query string. Sound plays through miniaudio's Web Audio output and starts with the first click, key or
  touch. The user directory lives in memory.
- In an offscreen run the browser's timers drive the frames, so a hidden or headless page runs a scripted check at
  full speed. Downloads are mapped at submission and read between frames, so a frame on the screen that reads back
  a little data keeps its swapchain texture.
- Tools:
  - `tools/web_check.mjs` runs a page's scripted checks in headless Google Chrome and compares the captures with
    golden images. `--onscreen` runs a page the way a person opens it.
  - `tools/check.sh step web` runs it on the sample and the demo.
  - `tools/publish_web.sh` assembles the demo and the sample as a static site with their licences, checks it, and
    with `--push` publishes it to the `gh-pages` branch for GitHub Pages.
- Safari: the page was black. Under a page zoom (115% on the user's Mac), SDL's probe of the canvas size measured a
  1 x 1 canvas a little under 1, so the window became 0 x 0. The app now gives the canvas its CSS size before it
  creates the window (the whole page; offscreen the `--window` size), so SDL takes the page's size and never
  measures the probe. A first fix, a patch of SDL's probe, was dropped for it.

### Vulkan

- The intermittent image-layout validation error on Vulkan through MoltenVK (`VUID-vkCmdDraw-None-09600`, a known
  issue since [0.12.0](v0.12.0.md#known-issues)) is fixed. Cause: SDL GPU's Vulkan driver defragments its memory at
  a submit and moved textures that the frame's command buffer, still open, had already bound; the engine submitted
  small command buffers while the frame's was open. The `SdlVulkanDefrag.cmake` patch defragments only when no
  other command buffer is open (reported as [libsdl-org/SDL#16685](https://github.com/libsdl-org/SDL/issues/16685)),
  and the rain's cover readback is now recorded into the frame's command buffer.
- `gpu::CommandBuffer::completionFence()`: a fence taken before the submit, for work recorded into a command buffer
  that someone else submits (the app's frame).
- A game from `templates/game` has a `web` preset. The quench-game skill describes the web build.
- From now on every release also deploys the web demo (`AGENTS.md`, "Versioning and releases").

## What was not verified

- Real Windows hardware, Vulkan on Windows, sound on Windows. Ray tracing on Windows does not exist yet (stage 15,
  parts 2 and 3).
- The browser build in Firefox, on another system or on a phone, touch input in a browser, sound by ear, long runs
  and memory growth. Nobody has played it with keyboard and mouse beyond opening sections.
- No GPU unit tests run on the WebGPU backend: it is covered by the apps' scenarios and captures.
- No iPhone run for this release.

## Known issues

- Web: there are no threads, ray tracing, GPU timing or HDR output. Depth textures and, where the adapter lacks
  `float32-filterable`, 32-bit float textures are sampled with nearest filtering. A capture or a GPU wait in a
  frame on the screen loses that frame. The user directory does not outlive the page.
- Web: the demo downloads about 19 MB; no size or load-time work was done.
- The engine's SDL carries `SdlVulkanDefrag.cmake` until an SDL release fixes
  [libsdl-org/SDL#16685](https://github.com/libsdl-org/SDL/issues/16685). Other work still submits command buffers
  of its own while the frame's is open (texture uploads, lazy initialization, the skinning with pass timing on);
  without the patch those could hit the same error.

## Changes for games

- `gpu::Backend` has a new value, `WebGpu`, and `gpu::ShaderFormat` a new value, `Wgsl`. A `switch` over either
  without a default now warns about the missing case.
- `gpu::ShaderBlob` has a new member, `wgsl`. Shader tables written by `quench_add_shaders()` fill it in web builds.
- A web build of a game needs the `web` preset of `templates/game/CMakePresets.json` (with `QUENCH_HOST_SHADERC` and
  `QUENCH_HOST_COOK` from a `host-tools` build) and Homebrew's Emscripten. The skill's "Web" section explains it.
- The engine's own SDL carries two more patches, `SdlLevelSize` and `SdlVulkanDefrag`. TrailForge declares its own
  SDL before fetching the engine, so its SDL is unchanged. Ashfall does not build on the engine.
- `gpu::CommandBuffer::completionFence()` is new. A `Fence` from it or from `submitWithFence()` of the same command
  buffer is one fence; `Device::isSignaled` is false before the submit and after a cancel, and `Device::wait` on a
  fence of a command buffer that was not submitted is a programming error.
- Web: the app sets the canvas's CSS size (position, width and height) before it creates the window, and SDL's
  fill-document window is no longer used. A page of a game's own that gives the canvas a CSS size of its own is
  overridden; the default page (`cmake/shell.web.html`) lost its `#stage` element.
- The SDL GPU backend now pushes fragment uniforms again after a blit or a mipmap generation. A game that relied on
  the blit's uniforms remaining bound (none known) would see its own uniforms instead.
- MSVC builds use `/W4 /WX` for engine targets when the engine is the top-level project; inside a game,
  `QUENCH_WERROR` stays off as before.
