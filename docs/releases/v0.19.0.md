# Quench 0.19.0

2026-11-14. A live, full-duplex spoken conversation with OpenAI's GPT-Live (`gpt-live-1`), asked for by the user for
Outpost: instead of the turn-based assistant (record, transcribe, a chat model with tools, synthesise: about 4 s a
turn), the player simply talks to the station: it listens all the time, answers by voice, yields when interrupted
and operates the game through the same tools. Changes since [0.18.0](v0.18.0.md). Source only.

**Against the real service only from the Mac, with spoken files.** No real microphone has talked to a session yet,
nothing ran on an iPhone, and a browser has no path to GPT-Live in this release (it needs WebRTC).

## What changed

- **WebSocket in `quench_net`** (`include/quench/net/WebSocket.h`, `FakeWebSocket.h`; [Network](../net.md#websocket)).
  `net::WebSocket`: `connect(WsConnect, WsHandlers)` with a URL and headers, `sendText`, `sendBinary`, `ping`,
  `close(code, reason)`, `abort`, `update()` once a frame; whole messages, the handlers (`onOpen`, `onMessage`,
  `onPong`, `onEnd` exactly once) on the main thread only; states and `WsEnd` (close code and reason, the HTTP status
  of a refused upgrade, a readable error). wss only except the loopback address; header values, messages and query
  strings never logged; a received-message limit (4 MB by default, NSURLSession's `maximumMessageSize`); connect,
  close and pong timeouts. Backends: NSURLSessionWebSocketTask on macOS and iOS, none elsewhere (the browser
  included: its WebSocket cannot send an Authorization header), and `net::FakeWebSocketServer` for tests (upgrades
  answered by URL, scripted messages, closes and failures with delays, handlers that answer like a server). The
  local test server (`tests/net/net_test_server.py`) also speaks WebSocket.
- **The microphone's streaming mode** (`MicDesc::stream`; [Audio](../audio.md#streaming)): the resampled samples go to
  `takeStream()` while it records, without a length limit, at the asked rate (24 kHz for GPT-Live), a bounded
  buffer (`streamBufferSeconds`), `setStreamMuted()` (silence, the input stays open), the same meter, permission and
  fake source.
- **`audio::VoiceStream`** (`include/quench/audio/VoiceStream.h`; [Audio](../audio.md#streamed-playback)): a
  generator that plays mono PCM pieces as they arrive, on a bus the game names: an 80 ms jitter buffer, fades at
  underruns, starts and flushes (no clicks), `flush()` for an interruption, `level()`, `audible()`, `active()`, the
  played position.
- **`assistant::LiveSession`** (`include/quench/assistant/Live.h`; [Live session](../live.md)): GPT-Live's primary
  WebSocket with Responses delegation. `LiveSettings` (the key in memory only, the model, the voice, the voice
  model's instructions with the docs' delegation template, the backend model `gpt-6-luna` and its instructions, the
  audio rate, the idle time, the gate, prices). The game's `ToolRegistry` as the backend's function tools; calls run
  one per `update()` with the registry's schema check, results as `function_call_output` items and one
  `response.create` per response (parallel calls included; if `response.completed` does not come within 15 s of the
  last result, `response.create` goes out anyway, once, with a log line). Microphone samples in (100 ms PCM16
  pieces), audio out, both transcripts as they stream, states for a UI, the game's events as context
  (`appendInstructions`, `appendThinking`, `appendCommentary`), the uplink gate for loudspeakers (silence instead of
  the microphone while the station is audible), usage and cost from the server's seconds and the backend's tokens,
  the idle close (45 s without speech by default), a reconnect at expiry with the conversation's text, cancel.
  `ToolRegistry::responsesTools()` and `assistant::base64Decode()` are new beside it.
- **The turn-based assistant for a game's own turns** (asked for by Outpost's "callbacks": the station decides and
  speaks when something happens; [Assistant](../assistant.md)):
  - **Turns the game starts**: `AskOptions::source = InputSource::Event` puts the input to the model under
    `Game event (not the player):` (`setEventHeading()` renames it; the one place the marking is made) instead of
    the player's heading, in the request and in the history; per-turn `AskOptions::maxRounds` and `maxActions` (a
    cap on calls of tools not marked `readOnly`; a call over it is refused to the model with the reason,
    `Stats::refusedCalls`). States, cancel, events and stats as for a player's turn.
  - **Cached tokens**: `Usage::cachedTokens` and `cacheWriteTokens` from `usage.prompt_tokens_details`
    (`cached_tokens`, `cache_write_tokens`, as OpenRouter documents them), in a round's and a turn's `stats()`, the
    totals and the round's log line. The chat body's keys are now written in a fixed order, the static part first
    (`model`, the settings, `tools`, then `messages` with the system prompt first, `tool_choice` last): it was the
    map's alphabetical order, which put `messages` before `tools`. `ProviderSettings::cacheMarker` (off) writes
    Anthropic's `cache_control` breakpoint on the system prompt (for Anthropic's models through OpenRouter).
  - **The history by a token budget**: `Limits::historyTokens` (6000 estimated tokens, 3 characters each) replaces
    the fixed 6 turns (`historyTurns` is now -1, no count, and still caps when set); the oldest turns go first, the
    newest stays uncut (its tool results as sent), older tool results are cut to `historyToolResultChars`, event
    turns `historyEventTurns` (3) old keep only their first line and answer. `historyJson()`/`setHistory()` keep
    their shape; 0.18.0's saves load. `estimateTokens()` and `historyTokenEstimate()` are new.
- **A manual check**, `examples/live_check` (`quench-live-check`; macOS, no window, the key from `OPENAI_API_KEY`
  only): a spoken question from a WAV file through the fake microphone in its streaming mode, an optional second
  voice over the answer, every stage with its milliseconds, the answer's audio to a WAV; and `--talk`, for a person:
  the real microphone and output, the levels of the echo, the station's stops classified.
- **Docs:** [Live session](../live.md) (new), [Network](../net.md), [Audio](../audio.md), [Assistant](../assistant.md),
  [Platforms](../platforms.md), the roadmap, and the `quench-game` skill (`SKILL.md`, `reference.md`: a game running a
  session with two tools).

## What was not verified

- A real microphone into a session, loudspeakers and their echo (whether `gpt-live-1` interrupts itself when it hears
  its own voice: `quench-live-check --talk` is there for the user to measure it), headphones.
- An iPhone (the WebSocket backend is the same NSURLSession code; its fake-server and local cases are macOS and
  Simulator only), long sessions, the idle close, the expiry and the reconnect against the real service (only with
  the fake), parallel calls from the real backend.
- Nobody has listened to `VoiceStream`'s output.

## Known gaps

- No browser path: GPT-Live in a browser needs WebRTC (a later stage); there is no WebSocket backend in web builds,
  on Windows, Linux or Android.
- With the uplink gate on (the default, for loudspeakers) the player cannot interrupt the station; barge-in on
  loudspeakers needs echo cancellation (Apple's voice-processing I/O unit is not wired in).
- Not there: custom voices, audio fixtures, forked or stored sessions, client and Decisions delegation, typed input
  to the backend, sideband connections.
- The documentation is silent on the session's duration limit on a WebSocket (seen: two hours), the pacing of the
  audio (seen: real time, silence included), what an interruption looks like (seen: nothing) and the error codes of
  a refused model or tier (the session's mapping of a start error guesses from the code's words).
- Each open second costs money on the player's key, silence included (0.05 US dollars a minute on 2026-11-14): a
  game must show when a session is open.

## Changes for games

Nothing has to change in a game's code or build: a game that uses none of this builds and runs as before.

- **WebSocket.** Keep a `net::WebSocket`, call its `update()` once a frame; macOS and iOS only. [Network](../net.md).
- **Live session.** Keep an `assistant::LiveSession`, call its `update()` once a frame, set the player's key and the
  instructions, add the game's tools (the same `assistant::Tool`s as for the `Assistant`); start the microphone in
  its streaming mode (`{.sampleRate = 24000, .stream = true}`) and feed `takeStream()` to `sendAudio()`; push
  `takeAudio()` into an `audio::VoiceStream` played on a bus, and report `setPlaybackActive(voice->audible())`
  (not `active()`: the server sends silence too). [Live session](../live.md).
- **Assistant.** Additive: `AskOptions` gains `source`, `maxRounds`, `maxActions` after `speak`; `Limits`,
  `Stats`, `Usage` and `ProviderSettings` gain fields at their ends; existing code compiles unchanged. Two defaults
  change behaviour: the history is kept by `historyTokens` (6000) instead of 6 turns (`historyTurns` is -1; set it
  to 6 for the old cap), and the newest history turn keeps its tool results as they were sent (up to
  `toolResultChars`) until the next turn. For events: `ask(text, {.source = assistant::InputSource::Event,
  .maxRounds = 2, .maxActions = 1})`, and queue an event that comes while a turn runs (one operation at a time).
  For Anthropic's models set `settings().cacheMarker = true`.
- **Microphone.** `MicDesc` has two new fields (`stream`, `streamBufferSeconds`) after `maxSeconds`: designated
  initializers keep working; positional ones of the first two fields too.
- A game gets this by moving its engine pin to this release and copying the `quench-game` skill again.

TrailForge (pinned `d708783`) and Ashfall (its own code) are not affected until they move.
